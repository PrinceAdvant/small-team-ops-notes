Small Team Ops Notes

Shared configuration across many services: scopes that keep secrets tidy

Once you run more than a handful of services, the same values start appearing everywhere: an SMTP password, an error tracking DSN, an organization API key. Copying them into each service works until you need to rotate one. Then you are hunting through ten settings pages and hoping you found them all.

Sort values by scope

Most configuration falls into one of four scopes:

  • Organization wide: values every project might need, such as a shared SMTP relay or logging endpoint
  • Project wide: values shared by the services of one product, such as a database URL used by both web and worker
  • Server wide: values tied to a machine, such as a local cache address or region name
  • Service specific: values only one app uses, such as its own session secret

Write this list down for your current setup. It usually reveals a few values duplicated in many places.

Define once, reference many times

Store shared values once at the right scope and have services reference them. When the SMTP password changes, you update one entry and redeploy the services that use it.

Keep build-time values separate

Some frameworks bake environment variables into the build, for example NEXT_PUBLIC_* in Next.js or VITE_* in Vite. Changing these requires a rebuild, not just a restart. Mark them clearly so nobody expects a restart to pick up the new value.

Naming conventions help

Prefix shared values by system: SMTP_HOST, SMTP_USER, SENTRY_DSN. Avoid generic names like KEY or TOKEN that collide between services.

Rotation routine

  1. Create the new credential at the provider
  2. Update the shared value
  3. Redeploy dependent services
  4. Confirm they work
  5. Revoke the old credential

Having one place to change makes this a ten minute task instead of a project.

Who can see what

Shared values are often the most sensitive ones. Restrict who can read organization-wide secrets, and log changes. A developer who needs to deploy one service rarely needs to read the production payment key.

Clean up regularly

Unused shared values pile up. Every quarter, check which ones are still referenced and delete the rest. Fewer secrets means fewer things to leak.
