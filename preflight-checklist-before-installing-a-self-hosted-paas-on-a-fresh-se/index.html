Preflight checklist before installing a self-hosted PaaS on a fresh server

Installing a self-hosted PaaS usually takes a few minutes. Fixing an install on a server that was not ready can take an evening. This preflight list catches the usual problems before you run any install script.

Operating system

  • Use a current LTS release, such as Ubuntu 24.04 or Debian 12
  • Apply updates and reboot once: apt update && apt upgrade, then reboot
  • Set the hostname and timezone so logs make sense later

Resources

  • At least 2 GB of RAM for the platform plus a small app. 4 GB is more comfortable if builds run on the same machine.
  • 30 GB or more of disk. Docker images and build caches grow faster than people expect.
  • Add a small swap file on low memory servers to survive build spikes.

Network and DNS

  • Note the public IPv4 and IPv6 addresses
  • Create DNS records for the dashboard and for a wildcard such as *.apps.example.com if you plan to use generated subdomains
  • Make sure ports 80 and 443 are reachable. Certificate issuance fails silently if a cloud firewall blocks port 80.

Firewall

  • Allow 22, 80 and 443 only
  • Check the provider's firewall as well as the host firewall
  • Remember that Docker manipulates iptables directly, so host firewall rules alone do not protect published container ports

SSH

  • Log in with keys, disable password authentication
  • Create a non-root user with sudo for daily work
  • Keep a second session open while changing SSH settings so you cannot lock yourself out

Docker

  • If the platform installs Docker for you, do not preinstall a different version
  • If you install it yourself, use Docker's official repository rather than the distribution package

Decide where the control plane lives

Some platforms let you run the dashboard on your own server or use a hosted control plane and only connect application servers. Hosting it yourself gives full data residency; using a hosted one means one less thing to back up and update. Decide before installing.

Backups from day one

Plan where database dumps will go, for example an S3 compatible bucket, before you deploy anything important.

After install

  • Log in, enable two-factor authentication
  • Deploy a test app with a domain and HTTPS
  • Reboot the server and confirm everything comes back
